# Elliott Wave Training

## Stage 3 — Elliott AI Trainer

Run from the project root:

```powershell
py -3 scripts\\train_elliott_ai.py
py -3 -m pytest -q
```

The trainer reads `Dataset/generated/weak_structure_labels.jsonl` and trains a separate Elliott morphology model. It uses only candidates marked both `training_eligible` and `hard_valid`.

### What it learns
- Candidate morphology from leg sizes, leg ratios, durations, direction and timeframe.
- Weak pattern classes currently available: `impulse`, `zigzag`, and `flat_candidate`.
- An unsupervised representation using `StandardScaler + PCA + MiniBatchKMeans`; all transforms are fitted on the training period only.
- A Random Forest classifier with sample weights derived from the heuristic rule score.

### Leakage controls
- Chronological 70/15/15 train/validation/test split.
- A 24-hour purge at both time boundaries.
- Scaler, PCA, clustering and classifier are fitted only on the training split.
- Held-out predictions are written separately; no test labels are used for fitting.

### Outputs
- `Models/elliott_structure_model.joblib`
- `Training/stage3/training_metrics.json`
- `Training/stage3/heldout_predictions.jsonl`

### Critical interpretation
Labels are generated by the existing Elliott rule engine. Validation/test metrics therefore measure agreement with those weak labels, not expert wave-count accuracy, future market prediction, or trading profitability. The high agreement is expected because the model learns geometric rules that also produced the labels. Confidence scores are raw model scores, not calibrated probabilities. This model is a research component and is not approved for live trading. Independent labels, more Elliott pattern families, and a separate forward predictive evaluation are still required.


## Stage 4 — Multi-Timeframe Reasoning

Run from the project root:

```powershell
py -3 scripts\\run_multitimeframe_reasoning.py
py -3 -m pytest -q
```

The reasoner builds causal snapshots from Stage-2 structural candidates across D1, H4, H1, M15 and M5. It keeps up to three recent alternatives per timeframe within explicit age limits, creates directional scenario alternatives, and links adjacent timeframe candidates only when their time intervals overlap or one interval contains the other.

### Reasoning policy
- D1/H4 are treated as higher-degree context; H1/M15/M5 provide progressively finer context.
- An opposite lower-timeframe leg is not automatically called a conflict: it may be a normal countertrend correction inside a larger structure.
- A direct D1/H4 direction disagreement is flagged; H4/H1 disagreement is flagged only for overlapping structures without parent/child containment.
- Competing up/down scenarios are retained rather than collapsed into one forced wave count.
- The engine abstains when coverage is insufficient, a higher-degree conflict remains, or close competing scenarios cannot be separated.
- Per-timeframe age limits: D1 10 days, H4 4 days, H1 48 hours, M15 18 hours, M5 6 hours.

### Outputs
- `Evaluation/stage4/multitimeframe_scenarios.jsonl`
- `Evaluation/stage4/stage4_report.json`

### Important limitations
The Stage-2 candidate labels remain weak rule-engine hypotheses, not expert-confirmed Elliott counts. Stage-3 held-out outputs are used only as a small auxiliary morphology bonus when timeframe, availability timestamp and weak pattern label match; this is not a unique candidate join and its raw score is never treated as probability. The Stage-2 candidate schema does not provide a verified invalidation price; the reasoner explicitly reports invalidation as unavailable rather than inventing a level. Scores are heuristic rankings, never calibrated probabilities or trade signals. This stage is structural research, not live-trading authorization.


## Stage 5 — Five-Year Daily Walk-Forward Simulator

Run from the project root:

```powershell
py -3 scripts\\run_elliott_walk_forward.py
py -3 scripts\\finalize_stage5_report.py
py -3 -m pytest -q
```

Default settings:
- Five-year validated EURUSD BID history, M5/M15/H1/H4/D1.
- Daily forecast cutoff: 17:00 America/New_York, DST-aware.
- Predict the next completed NY session's close direction (UP/DOWN/FLAT, 5-pip deadband), close return and high/low excursions.
- 180-session initial warm-up.
- Expanding-window training, model refresh every 5 sessions; labels are only used after the target session has completed.
- Stage-4 context is joined with an as-of timestamp lookup; snapshots after the forecast cutoff are never visible.
- 131 features in the completed run, including 18 Stage-4 context features.

### Outputs
- `Evaluation/stage5/daily_walk_forward_predictions.jsonl` — immutable-by-cutoff historical predictions with actual outcomes and Stage-4 scenario context.
- `Evaluation/stage5/walk_forward_metrics.json` — classification, baseline, coverage and regression metrics.
- `Evaluation/stage5/walk_forward_report.md` — human-readable evaluation.
- `Models/daily_elliott_forecaster.joblib` — latest expanding-window classifier/regressor bundle.
- `scripts/finalize_stage5_report.py` — attaches causal Stage-4 scenario context and calculates detailed diagnostics for the saved forecasts.

### Five-year run results (2021-11-20 to 2026-11-20)
- 1,301 NY cutoffs; 180 warm-up sessions; 1,121 forecasts; 1,120 evaluated outcomes.
- Direction accuracy: 41.43%; majority-class baseline: 46.34%.
- Balanced accuracy: 34.09%; macro F1: 34.11%.
- Non-conflict forecast coverage: 62.23%; accuracy among non-conflict forecasts: 38.02%.
- 423 evaluated forecasts were marked CONFLICT (abstain).
- Regression MAE: close return 38.16 pips; high excursion 26.07 pips; low excursion 24.61 pips.
- Stage-4 snapshot coverage at forecast cutoffs: 100%.

### Interpretation
The current five-year model does **not** demonstrate predictive edge: raw direction accuracy is below the majority baseline, and accuracy on non-conflict outputs is also weak. This is a valuable negative result, not a reason to hide the metric or tune on the same test period. The forecasts are research artifacts, not trade signals. Next work should focus on stronger structural targets, regime-aware evaluation, calibrated uncertainty, and comparisons against simple baselines on untouched future data.

## Stage 6 — Automatic Evaluation & Retraining Governance

Run from the project root:

```powershell
py -3 scripts/stage6_evaluate_and_govern.py
```

Stage 6 consumes the immutable Stage-5 chronological forecast ledger. It compares
the classifier against two causal baselines: an expanding majority-class baseline
and previous-session direction persistence. Baseline predictions at origin t use
only actual outcomes observed before t. The first origin is excluded from the common
comparison because no prior outcome is available.

The evaluator reports accuracy, balanced accuracy, macro F1, per-class metrics,
confusion matrices, yearly breakdowns, abstention/coverage, Wilson accuracy
intervals, and paired moving-block bootstrap intervals for accuracy differences.
The bootstrap uses 10-origin blocks to partially account for serial dependence.
Classifier vote shares are not calibrated, so Brier score and log-loss are omitted.

Promotion is gated by a minimum sample size (250 by default), statistically
positive block-bootstrap accuracy differences against both causal baselines,
and balanced accuracy no worse than the expanding-majority baseline. No
hyperparameter tuning is performed on the evaluation outcomes. A candidate that
fails is archived but cannot replace the champion pointer. If no champion exists,
the registry explicitly records NO_VALIDATED_CHAMPION.

Outputs:
- Modules/Elliott_Waves/Evaluation/stage6/stage6_evaluation.json
- Modules/Elliott_Waves/Evaluation/stage6/stage6_report.md
- Versioned candidate archive and manifest under Modules/Elliott_Waves/Models/registry/

Important: Stage-5 history has already been inspected and used for research
decisions. Stage-6 metrics are governance/audit evidence, not a fresh untouched
holdout. Prospective forecasts must accumulate before claiming generalization.
Raw feature vectors were not persisted with Stage-5 forecasts, so Stage-6
currently monitors outcome/performance drift by year; feature-level PSI/KS
monitoring requires saving timestamped feature snapshots in a future run.

### Stage-6 pipeline runner

Evaluate the existing Stage-5 ledger:
```powershell
py -3 scripts/run_stage6_pipeline.py
```

Refresh the complete Stage-5 walk-forward first, then run Stage 6:
```powershell
py -3 scripts/run_stage6_pipeline.py --refresh-stage5
```

Stage 5 already refits its expanding-window candidate every five sessions.
The pipeline runner chains that simulation to Stage-6 governance; a failed
Stage-6 gate leaves the champion pointer untouched.

## Stage 7 — Daily Elliott Forecaster

Run from the project root:
```powershell
py -3 scripts/daily_elliott_forecaster.py
```

Outputs:
- Modules/Elliott_Waves/Evaluation/stage7/daily_elliott_forecast.json
- Modules/Elliott_Waves/Evaluation/stage7/daily_elliott_forecast.md

The report uses the latest M1 close as the market reference and the latest Stage-4
snapshot available at or before that timestamp. Stage-4 candidates are joined to
Stage-2 weak labels by exact timeframe, pattern, and availability timestamp.
Confirmed swings available in the prior 90 days provide empirical H1/H4 target
ranges (25th–75th percentiles); no fixed Fibonacci projection is used.

Invalidation references use the latest confirmed opposing H1/H4 swing endpoint.
They are explicitly technical proxies, not verified Elliott rule invalidations.
All heuristic rankings remain non-probabilistic. Competing scenarios are retained.

Automatic abstention occurs for stale market data (>24 hours), stale Stage-4
context (>6 hours), insufficient timeframe coverage, conflicts, Stage-4 abstention,
or missing swing context. A stale-data report may still display scenarios for
research, but its overall decision is ABSTAIN. The next session date advances
from the current New York date, not from an old historical candle date.

Current limitation: the source CSV currently ends at 2026-11-19 23:58 UTC.
Until newer market data is downloaded, Stage 7 correctly abstains for the next
session rather than presenting an outdated Thursday count as a live forecast.
