# Phase 16 — Controlled Source-to-Observation Ingestion

## North Star capability advanced

Gate 1 — reliable canonical data plane. Phase 15 created a point-in-time observation sink. Phase 16 adds the explicit execution bridge that carries a registered source adapter result into that sink. This shared path is intended for future quantitative/statistical, macro/fundamental, intermarket, positioning, and sentiment data products; it is not a Price Action feature.

## Repository gap addressed

The repository had typed adapter contracts and a registry, and now has an append-only point-in-time store. Before this phase, there was no single service enforcing the sequence:

1. verify source and product registration;
2. verify that the source is enabled;
3. select an explicitly registered adapter for that exact source/product;
4. execute the adapter with a typed FetchRequest;
5. validate the returned FetchResult and its source/product identity;
6. stamp retrieval time at the execution boundary; and
7. persist the stamped result in PointInTimeObservationStore.

Without this bridge, adapters and the store were separate capabilities and callers could accidentally omit retrieval-time stamping or route data under the wrong identity.

## Deliverable

`source_registry/ingestion.py` adds `SourceObservationIngestion`, an injected, deterministic orchestration boundary.

- The caller supplies a registry document that has already passed `load_registry` validation.
- Adapters are explicitly injected and keyed by `(source_id, product_id)`; there is no implicit provider selection.
- The service rejects unknown sources, disabled sources, unregistered products, and missing adapters before fetching.
- Adapter output must be a valid `FetchResult` whose source/product identity exactly matches the request.
- Retrieval time is generated by the execution layer, normalized to UTC, and applied with `FetchResult.with_retrieved_at`.
- Only after all checks pass is the result persisted through the Phase 15 store.
- A compact `IngestionSummary` reports the observation count and persistence outcome.

The clock and store are injectable so the full path can be tested deterministically without network access.

## Integration path

`validated source_registry/registry.json` → explicit adapter map → `SourceObservationIngestion` → `FetchResult` validation and retrieval-time stamping → `PointInTimeObservationStore` → strict `get_as_of` reads for downstream specialists.

The existing Fed adapter can be injected for its declared target-range product when a caller supplies its records provider. This phase does not instantiate a provider, fetch the internet, or claim that all registered sources have working adapters. An unregistered adapter remains unavailable and fails closed.

## Acceptance criteria

- Unknown, disabled, or unregistered source/product requests fail before adapter execution.
- Missing adapters fail closed; no fallback provider is guessed.
- Adapter exceptions propagate and do not persist partial data.
- Non-FetchResult, invalid, or mismatched-identity adapter outputs are rejected.
- Retrieval timestamps must be timezone-aware and are stamped by the ingestion boundary in UTC.
- A successful run persists the result and makes it visible to a correctly scoped point-in-time query.
- Repeating an identical ingestion is idempotent through the Phase 15 store.
- Focused ingestion tests and the full existing unittest suite pass on the exact PR head SHA.

## Explicit non-goals and safety

- No network client, source-specific scraper, provider credentials, scheduler, automatic retries, or background worker.
- No automatic execution of registry entries with `auto_fetch`; this service is explicitly invoked by a caller.
- No claim that ECB or every other registry entry has a connected adapter.
- No mutation of the source registry, operational source-state database, MT5 candle store, calendar/news stores, or RAG/knowledge databases.
- No macro/fundamental interpretation, quantitative signal, cross-domain vote, or directional authority.
- No strategy, risk, BUY/SELL, MT5 order, or live-execution changes.
